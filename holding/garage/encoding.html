Thumbnail encoding study shipped

Every grid thumbnail is the end of a chain of choices — format, quality, chroma subsampling, resolution. Here's one photo run through all of them with real byte counts, so the tradeoffs are visible instead of folklore. All numbers are from the actual encoders the site uses (avifenc, jpegli, cwebp, sips).

The verdict shipped: the live pipeline (holding/scripts/add-photos.sh) encodes every thumbnail as AVIF-primary + a jpegli q82 JPG fallback — the winning combination below. That's why the site builds jpegli from source.

Format showdown

The same detailed color frame at 400×266px. PNG is the lossless baseline; everything below it is lossy. Eyeball the quality, then read the bytes — b/px = bytes per pixel, the size-density that actually scales.

Why the site builds jpegli from source

Look at the two q82 JPEGs above: system/sips lands at 31.7 KB, jpegli at 16.8 KB — same nominal quality, ~47% fewer bytes. Google's jpegli is a psychovisually-tuned re-implementation of libjpeg; that win is the entire reason ~/.local/bin/cjpegli exists and the pipeline shells out to it instead of using the OS encoder. AVIF beats both, but JPEG is the universal <img> fallback, so making it small still matters.

Grayscale: drop the chroma planes

A black-and-white Leica frame (400×267). For a grayscale image the two chroma planes carry almost nothing, so AVIF 4:0:0 (luma only) is both the honest encode and rules out any faint color cast. The byte saving over 4:2:0 is tiny because there was nothing in those planes to begin with — the point is correctness, not size. The pipeline auto-detects sips -g space → Gray and switches to --yuv 400.

Resolution scales bytes ~quadratically

The color frame at three long edges, AVIF q63 vs jpegli q82. 2× the long edge ≈ 3× the bytes, and AVIF holds a steady ~35–38% lead over JPEG at every size — which is why the grid is AVIF-primary and kept to a small square.

What aadhar.sh actually ships

  • AVIF primary (q63, 4:2:0 color / 4:0:0 gray) + jpegli JPG q82 as the universal fallback — via <picture>.
  • Pre-cropped 600/400 squares, metadata-stripped: the file is the displayed pixels, so no off-square or EXIF bytes ride along.
  • 4:2:0 over 4:4:4 for color — 4:4:4 stores the full chroma and costs ~8% more bytes (the two AVIF q63 cards above) for no visible gain at thumbnail size, so 4:2:0 is free quality.
  • Full-res share copies in R2 at JPEG q95 — visually lossless, half the bytes of q100; the true HEIF originals stay on local disk.
