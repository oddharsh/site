Trading page scripts for CSS changes keyboards more than bytes

Aleth Gueguen's Go fast? Go web native at performance.now() 2026 closes on a question it leaves open: can the JavaScript behind an interactive element give way to modern HTML? Five stacked PRs here tried it on 22 pages, under one claim: functionally identical. This page measures that claim in Chromium 158, Firefox 159 and WebKit 27.2. It checks pixels at load and after every press, bytes on the wire, work per press, the keyboard, and how the browser's own controls sit next to Luna.

The stack takes 164.6 KB of inline script on these pages down to 131.8 KB. 7 pages now ship no inline script at all, so the Worker sends them its strictest script-src. The documents a visitor downloads barely move, because brotli had already squeezed the script into a few hundred bytes and the markup that replaces it compresses just as well. PR 1891 removes 28.7 KB of raw script and its pages shrink by 254 B in total. /restore grows by 2,211 B, since each of its 131 restore points now ships a preformatted date.

So bytes are not the argument for this. What changes is behaviour, and that is what the rest of the page measures.

Pixels decide what counts as identical

Each page loads three times: twice from the commit the PR sits on and once from the PR. Playwright screenshots all three, then presses every button, radio, checkbox and summary the old page offers, in both, and screenshots the section around it. A state counts as identical only when every RGB value matches. The two loads of the old page are the control. A page that differs from itself, like the homepage's now-playing track or masonry's shuffled photos, reads "changes on reload" and is judged by its text alone.

What the oracle caught

  • gpt56 shows all three readouts at once. PR 1891 hides the unpicked readouts with .sol-ro{display:none} and then, later in the same sheet, gives every readout .readouts{display:grid}. Same specificity, later rule wins, so the "bytes" and "ship" numbers sit under the meter from first paint.
  • hidden-flags stripes unevenly when filtered. The script rebuilt the table on every click, so :nth-child(odd) striped the rows you could see. CSS that hides rows keeps them in the count. :nth-child(odd of [data-g=config]) stripes among the rows a filter keeps, which is what the HTML twin above does. The PR also adds about 15 px of space under the demo.
  • tee keeps the picked attack pressed. The buttons used to spring back; the radios stay down. That one reads as an improvement.
  • fuse's first demo works again. On the commit the stack starts from, pressing "flash this build" throws e.appendChild is not a function. The build minifies inline scripts under a filename with no .js extension, so Oxc parses them as strict modules. In a module, a function declared inside an if block belongs to that block, so the mangler reuses its name. The browser runs the script in sloppy mode, where that function also lands in the enclosing scope, and the two names collide. PR 1891 fixes fuse by accident, since its rewrite drops the block. 9 of 72 inline scripts minify differently once the filename ends in .js.
  • gpt56 keeps its glossary link. The old script rewrote the copy with textContent, so "preload" lost its link after one round trip, and the meter loaded at 68 percent where its data said 74. One radio state per panel removes both.

Time is a tie until the table gets long

Two instruments timed each press. The first runs from the click to a task queued behind the next animation frame, which is what a reader waits for. The second times the work alone: script, style and layout, forced by reading offsetHeight straight after the click. The fixtures were served cross-origin isolated, so performance.now() resolves below a millisecond in all three engines.

On a table, content-visibility does nothing in any engine: a table row is an internal table box, size containment has no effect on one, and the cells report themselves rendered. Radios change four things a keyboard user meets. In Chromium and Firefox the JS tabs are 3 Tab stops and the JS filter is 8; each radio group is 1, and the arrow keys move the pick. Enter picks a button and does nothing on a radio. Firefox restores a checked radio on reload, where every JS twin starts over; autocomplete="off" on the inputs keeps the old behaviour. And the accessibility tree reads radio [checked] where it read button [pressed]. PR 1891 makes that trade on eight pages and its body doesn't mention it. gpt56 also loses the aria-live that announced each new readout.

WebKit, like Safari by default, sends Tab past buttons and radios alike, so there both twins are reached the same way, with Option-Tab. The plain sibling twin has a cost the others don't. Its radios sit before the table so ~ can reach it, which puts them outside the fieldset that names them, and a screen reader hears eight radios with no group. The third twin on the bench wraps the whole demo in the fieldset and gets the name back.

The script has states the markup doesn't

Stéphanie Walter's Performance, As a Design Opportunity asks a team to design each state a component can be in: loading, taking longer, error, empty. Run her checklist on a JS twin and it has two states nobody designed. Before its script runs, the hidden-flags filter is an empty bar over an empty table. If the script fails, it stays that way, which is what fuse's first demo did for every visitor until the stack. With JavaScript turned off, the JS filter showed 0 rows and 0 filters in all three engines, and every CSS filter showed all 19 rows with 8 working filters.

What each PR needs before it merges

  • 1889 merges as is. typed-config now keeps its 13 bindings twice, in the table and in the picker's array, so one should derive the other.
  • 1890 merges for scroll, safari27 and pixel-peeper. Masonry leaves its masonry radio checked and reachable on browsers without grid-lanes, which is Safari 26 and Firefox, while the page shows fixed squares; the old code disabled the button.
  • 1891 got its fixes in 32d257b1: the gpt56 hide rule now outranks .readouts, the readouts sit in one aria-live region again, hidden-flags stripes with :nth-child(odd of S), and the body names the keyboard change on eight pages. Every hidden-flags filter state now matches the old demo pixel for pixel.
  • 1892 got its fixes in 9ff2441e: the drop zone's label holds the Tab stop, so Tab reaches it in all three engines, and the ask bar drops minlength, so a short query fails quietly as before with no browser bubble. The grip, the note close box and the /access tree hold the look.
  • 1893 needs /lens* excluded from the site's speculation rules. Its chips are now real links, and hovering one would prerender /lens?url=, which runs a full server-side inspection of a third-party site.

The trade is worth making where a page has a small, fixed set of states: it removes code that can break, as fuse did, and the demos keep working without JavaScript. It is a different control, though, and a pixel oracle is how you find out which parts of "identical" held.
